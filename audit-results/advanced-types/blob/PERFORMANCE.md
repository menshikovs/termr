# A2.4 performance

`bench-blob.R` measures in-memory DataTable rendering and formatting for 100,
10,000 and 100,000 list-of-raw rows. It also measures a blob-shaped S3 list
without requiring the optional `blob` package, and previews a 10 MiB raw value.
The script builds the test data before the timed render and formats only the
visible 20-row slice.

The checked-in CSV files are generated by running the script on Windows R
4.6.1. First-render samples were 10–20 ms per table, scrolling renders were
13–14 ms, and formatting 20 visible values took 1.2–1.4 ms across all three
row counts. Read-only edit rejection measured below the timer's resolution. A
10 MiB payload's eight-byte summary took about 0.01 ms; the resulting summary
object is 152 bytes. `Rprofmem` recorded zero bytes for that operation, which
does not prove zero small allocator activity. The implementation slices at
most eight bytes and never creates an encoded copy of the payload.

The profiler did not report small pooled R allocations, so these timings and
allocation records are indicative rather than a complete allocation census.
The real `blob` package was unavailable; the blob-shaped list uses the same
S3 list storage contract but is not a substitute for package-specific tests.
