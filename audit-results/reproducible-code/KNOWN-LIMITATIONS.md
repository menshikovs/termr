# Известные ограничения

1. DataTable сохраняет текущий вид, но не хронологию действий; экспорт не
   является operation history.
2. Pipeline требует вручную предоставить ту же версию объекта под именем
   `data`. Совпадение источника/версии автоматически не доказывается.
3. `table_source` query export, source edits, dbplyr/DuckDB query provenance и
   Arrow Dataset path/query export не поддерживаются.
4. Выделение из source-backed таблицы ограничено фактически прочитанными
   выбранными строками и только типами, чья schema сохранилась после чтения.
5. Поддерживается только закрытый перечень классов. `AsIs` list-column и
   пользовательские S3/S4 классы не проходят как обычные значения.
6. Для сложных атрибутов и optional classes точность гарантируется лишь для
   протестированных структур. Требуемый optional пакет должен быть установлен.
7. Правки записываются по позиции строки исходного объекта. Без стабильного
   ключа они не переживают перестановку/замену строк между версиями данных.
8. В коде edits пользователь должен иметь изменяемый объект `data`; remote
   write-back не производится.
9. Clipboard latency, большие интерактивные вставки и terminal-host
   совместимость не были сертифицированы в реальном RStudio/Positron.
10. Windows R CMD check не завершился без ошибки: тестовый пакет падает на
    17 processx запусках из-за `system error 5, Access is denied` при создании
    дочерних pipes в этом sandbox. Подробности — `TEST-RESULTS.md`.
11. WSL PTY harness стабильно фиксирует два отказа в независимом
    `combined_focus_session` (Enter после Tab в одной PTY записи не активирует
    кнопку). A4 не изменяет POSIX input driver/harness; baseline-прогон до A4
    не выполнялся, поэтому прежнее наличие дефекта не доказано.
