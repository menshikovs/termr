# Безопасность и приватность

- Генерация — data-to-code: AST строится из проверенных language objects;
  произвольный пользовательский код не исполняется.
- Имена колонок и строки кодируются как строковые литералы. Злонамеренное
  имя столбца не превращается в вызов или выражение.
- Функциональные фильтры и неизвестные классы не сериализуются.
- Для lazy/source-backed DataTable pipeline не содержит SQL, connection
  object, database path, query, environment variables или credentials.
- В operation model source identity обозначена как неизвестная; generated
  pipeline требует, чтобы вызывающий код предоставил `data`.
- Значения, выбранные пользователем для копирования, попадут в clipboard
  исходником. Это явный пользовательский вызов, а не сетевая отправка.
- Размер, число строк/ячеек и рекурсивная глубина ограничены. Превышение
  лимита возвращает `limited`, а не усечённый код под видом точного.
- Генератор не выполняет SQL, не записывает данные в remote source и не
  отправляет код внешним службам.

Тесты проверяют hostile column names, UTF-8 строки, parseability кода,
отсутствие изменения исходной таблицы и отказ для неизвестного класса.
Злоумышленный filter regex может быть тяжёлым при запуске сгенерированного
пользователем выражения; генератор не выполняет код и не меняет семантику
существующего фильтра. Код с пользовательским regex следует проверять перед
самостоятельным запуском.
